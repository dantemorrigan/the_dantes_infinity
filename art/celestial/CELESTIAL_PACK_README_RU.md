# Celestial Apocalypse — Minecraft Java 26.1.2

Три визуальных подпака: 01 — разрушение светил, 02 — метеоритный дождь,
03 — красное небо для дня и ночи. Содержимое resources/ каждого подпака
объединить в src/main/resources/ мода. Ни один файл не заменяет ванильные
текстуры глобально. Для поведения нужен код мода; это не готовый jar.

## Именно солнце и луна Minecraft

Версия взята из проекта. В 26.1.2 солнце находится в
textures/environment/celestial/sun.png, а луна — в восьми отдельных
textures/environment/celestial/moon/*.png. Старый moon_phases.png не используется.
Пути проверены по тегу misode/mcmeta 26.1.2-assets, commit
394aa1bf4c0fad7c76af57abadff6ded12aa411b.

PNG с трещинами — ПРОЗРАЧНЫЕ СЛОИ поверх оригинального активного светила,
а не нейросетевая перерисовка его поверхности. Так остаются точные пиксели
Minecraft и поддержка ресурспаков. В архиве нет скопированных базовых PNG игры.
Код берёт их из ResourceManager клиента и рисует трещины в тех же UV.
integration/celestial_layers.json задаёт пути, стадии и правило маскирования.
Обрезать по alpha И яркости исходного пикселя: чёрный фон может иметь alpha=255.
Для тонкого серпа и новолуния нельзя рисовать трещины во всю полную луну.

Если нужны отдельные СКЛЕЕННЫЕ PNG для редактора, запустить локально:
python3 tools/build_celestial_variants.py /path/to/26.1.2.jar
Нужен Python с Pillow. Скрипт использует оригинальные PNG из вашего клиента,
проверяет версию и генерирует стадии для солнца и всех восьми фаз луны.
Скрипт не нужен для динамического наложения в игре.

## Файлы

- 8 слоёв трещин: 4 стадии солнца, 4 стадии луны; размеры 32 и 64 px.
- Данные 16 UV-фрагментов, сохраняющих реальные пиксели выбранного светила.
- 6 JSON-моделей метеоритов: 3 солнечных, 3 лунных; ванильные материалы.
- Покадровые след, взрыв и ранее подготовленные ударная волна/дым/заряд.
- Красные дневное и ночное небо: панорамы и по 6 кубических граней.
- Таймлайн, радиус, цвет/туман, рекомендации по частицам и серверным событиям.

## Рендер и интеграция

integration/*.json — наши форматы описания. Нужны загрузчики/код; Minecraft
сам не запускает эти файлы. items/*.json тоже не регистрируют предметы.
Модели используют стандартный JSON и minecraft:block/* без своих замен породы.
Magma — анимированная ванильная текстура; glowstone даёт материал, но не
динамический свет автоматически. Свечение энергии/огня — full-bright слой.

В небе использовать настоящий трансформ и UV выбранного светила. Сначала
слабые трещины, затем большие разломы, после — 16 раздельных UV-частей,
которые летят к земле. Не заменять квадратное солнце реалистичной сферой.
Для метеоритов на земле использовать объёмные модели. Фиолетовый след
ориентировать по направлению движения; огонь и ударная волна — отдельные слои.
Текстуру следа не растягивать в неподвижный крест.

Под красным небом светила рисуются отдельно. Небо/облака/туман плавно
окрашиваются только внутри области события. Днём — красно-оранжевый свет,
ночью — тёмно-бордовый фон и читаемые огненные следы. Не меняйте реальное
время мира и не перекрашивайте все блоки в красный ради визуала.
Кубические грани: +Y вверх, UV от верхнего левого угла, см. sky_orientation.json.

## Пять минут

Дождь длится 300 реальных секунд с первого падения. 6000 тиков — только
эквивалент при 20 TPS; при лагах использовать серверный монотонный deadline.
На перезапуск сохранить wall-clock expiry. Базовый радиус 256 блоков,
переход цвета ещё 64 блока. Это настраиваемые рекомендации, не исполняемый код.
Разрушения, кратеры, взрывы и поджоги делает сервер. Клиентские дальние
метеоры декоративные. После окончания новые не спавнятся, небо возвращается,
созданные пожары продолжают работать по обычным правилам Minecraft.
Состояние уничтоженного светила хранить отдельно от временного красного неба.

Проверено: структура JSON, пути ресурсов внутри паков, координаты моделей,
PNG/alpha, комплект фаз. В Minecraft эффекты ещё не запускались.
